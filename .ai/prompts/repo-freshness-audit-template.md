# Repository Freshness Audit Template

Use this before a presentation, release, stakeholder meeting, onboarding session, publication, or architecture decision.

```text
Using the saved repo brief and the connected GitHub repository <owner/repo>, perform a freshness audit.

Goal:
Determine whether the saved repo brief is still reliable enough to use for <presentation/release/onboarding/API planning/publication>.

Check:
- repository purpose
- public functions, endpoints, chapters, or major components
- main workflows
- README, vignettes, examples, book chapters, or documentation
- tests, validation, render checks, or quality signals
- deployment, runtime, or publication assumptions
- dependencies
- versioning, gateway, or publication assumptions
- claims likely to appear in the deliverable

Return:
1. Freshness status: fresh / partially stale / stale
2. High-confidence unchanged areas
3. Stale or questionable areas
4. Specific corrections needed
5. Claims that must be verified manually
6. Suggested updated text for the affected sections of the repo brief
```
