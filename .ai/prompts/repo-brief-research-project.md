# Research Project Repository Brief Prompt

Use this for repositories containing papers, notebooks, analysis, model code, reports, or research workflows.

```text
Use the connected GitHub repository <owner/repo>.

I am not asking you to implement changes. I want a reusable repository briefing that I can save as a source in a ChatGPT Project.

This repository contains a research or analytical project. Analyze it as a research workflow, evidence system, documentation artifact, and reproducibility package.

Please produce a structured repo brief with the following sections:

1. Brief Metadata
- repository name
- branch analyzed, if visible
- commit SHA, if visible
- date analyzed
- access method
- confidence level
- known limitations

2. Executive Summary
Explain what research question, analysis, or policy problem this repository appears to address.

3. Audience and Use Cases
Identify intended readers, analysts, collaborators, reviewers, decision makers, or maintainers.

4. Research Question and Analytical Purpose
Identify the apparent research question, hypothesis, policy question, or analytical goal. Distinguish visible facts from inferences.

5. Repository Structure
Map important folders and files, including data, code, notebooks, reports, outputs, figures, tables, references, and documentation.

6. Analytical Workflow
Explain the sequence from raw data to final outputs.

7. Data Sources and Variables
Identify data sources, important variables, transformations, and limitations visible from the repo.

8. Methods and Models
Summarize methods, statistical models, assumptions, estimation workflows, and robustness checks if visible.

9. Outputs and Evidence Products
Identify papers, reports, tables, figures, dashboards, presentations, or datasets produced by the repo.

10. Reproducibility and Environment
Analyze package management, scripts, notebooks, execution order, seeds, environments, Docker, renv, lockfiles, or other reproducibility infrastructure.

11. Documentation and Research Notes
Summarize README files, code comments, notebooks, methodology notes, and instructions.

12. Validation and Quality Signals
Identify tests, checks, peer review traces, robustness checks, diagnostics, or gaps.

13. Interpretation Risks and Open Questions
Separate data limitations, methodological risks, evidence gaps, reproducibility gaps, and author questions.

14. Presentation-Relevant Story
Explain how this research project could be presented to technical or policy audiences.

15. Source Evidence
List files consulted and what each file supported.

Important rules:
- Do not invent details.
- Distinguish visible repo facts from inferences.
- Cite repository files or snippets wherever possible.
- Flag uncertainty.
- Avoid overclaiming research conclusions beyond what the repo supports.
```
